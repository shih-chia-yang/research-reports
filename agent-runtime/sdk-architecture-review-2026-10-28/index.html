架構缺口與建議完善順序

以下以目前來源與隔離探測結果判斷實作接點及缺口；建議順序供後續工程安排，人類尚未核准新的正式實驗設計。

CLI：輸入工作與流程

CLI 接收 --workitem 與 --routing 指定的檔案，檢查未知、重複及缺值參數。

WorkQueue：工作項目推進

WorkQueue 保存固定順序的工作項目，並在目前項目完成後移至下一個。多工作樹與完整試驗批次的協調尚未驗證。

RoutingRegisterService：流程與 COE 選路

RoutingRegisterService 管理 Flow／Node 的啟動、結果與轉移。輸入驗證要求每份 Routing 定義恰好有一條 COE Flow；缺漏或重複均拒絕；R1 smoke 未執行 COE 節點。完整 Implement Layer 指引的審查、核准、Expected／Lock 與比較尚未接入 C# Runtime。

AgentOrchestrator：協調與異常接續

AgentOrchestrator 協調 WorkItem、節點執行及快照保存。部分變更的識別、重派、重試與中斷後恢復仍需實測。

Adapter 與 Python SDK bridge：單次呼叫

AgentProcessAdapter 以 stdin／stdout 交換單筆 JSON；SDK bridge 執行一次 Codex SDK turn，回傳 session、turn、usage 及結果。Host 目前用固定環境變數設定 cwd，每次 AgentRequest 無獨立工作區欄位；多工作樹定位尚未接通。真 SDK 取消後的程序回收與部分輸出保存仍待驗證。

RuntimeService：執行與結果查證

RuntimeService 派送 Agent 請求、紀錄與解碼回覆、呼叫獨立查證，並在 completion 時查證 Git。SDK 回傳 completed 只是呼叫結果；工作是否通過仍由 C# 核對 Gate 及流程條件。

獨立 Gate：Scanner 與 Graph Comparator

預設 MechanicalVerifier 查驗檔案及 JSON 布林；隔離候選 GateToolVerifier 可依受控 registry／plan 選工具並核對摘要。smoke Gate 已呼叫 Scanner scan，宣告 coverage complete、相依 coverage partial。正式 C# Gate 需要補齊 Scanner 接點與 Graph Comparator，並分別處理觀測、Expected／Lock 及比較結果。

Gate plan／case map 須經審查更新，並從 TRX 確認新增案例真正執行。

RunStore、Trace 與試驗資料

RunStore 保存目前快照與版本歷程；TraceRepository 分開追加工作日誌及 Agent 原始回覆。正式試驗與不可重跑資料仍需要持久保存與明確取得方式。

完成實驗的建議順序

  1. 依已確認的 Implement Layer v2 指引，建立 C# Runtime 可執行的完整 Routing，核對人工核准與 Expected／Lock。
  2. 接入獨立 Scanner 與 Graph Comparator；更新並驗證 Gate 選案，保留 Scanner partial 與 Graph 比較各自的結果。
  3. 接通每次請求的工作樹定位；實測逾時、取消、COE、部分變更與恢復。
  4. 固定正式 trial 的輸入、資料保存與驗收條件後，執行研究試驗。
